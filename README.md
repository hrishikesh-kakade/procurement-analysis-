# Procurement Intelligence Platform

[![CI](https://github.com/<your-username>/procurement-platform/actions/workflows/ci.yml/badge.svg)](https://github.com/<your-username>/procurement-platform/actions)

A full-stack procurement system: supplier and material management, requisition approval workflows,
RFQs with quotation comparison, purchase orders and goods receipt, spend analytics with supplier
scorecards, an AI analytics assistant and a policy knowledge base with cited answers (RAG) — behind a
role-based React UI.

**Backend:** Python 3.11 · FastAPI · Pydantic v2 · PostgreSQL 16 · SQLAlchemy 2.x · Alembic · Redis (cache + RQ jobs) ·
Qdrant (vector search) · Anthropic API · Pytest
**Frontend:** React 18 · TypeScript · Vite · React Router · Recharts · nginx
**Ops:** Docker Compose · GitHub Actions

## Quick start

```bash
cp .env.example .env                                   # optional: set SECRET_KEY, ANTHROPIC_API_KEY, ...
docker compose up --build                              # db, redis, qdrant, api, worker, web
docker compose exec api python -m scripts.seed         # optional demo data
docker compose exec api python -m scripts.ingest_docs  # index the sample policy documents
```

| URL | What |
| --- | --- |
| http://localhost:8080 | Web app (sign in with the bootstrap admin below) |
| http://localhost:8000/docs | Interactive API docs (Authorize → sign in) |
| http://localhost:8000/health | Health check |

First admin (created on startup when no users exist; development defaults):
`admin@procurement-platform.dev` / `ChangeMe123!` — override with `ADMIN_EMAIL` / `ADMIN_PASSWORD`.
Create more users in the **Users** page, or `docker compose exec api python -m scripts.create_admin you@company.com`.

## What is in the box

| Area | Highlights |
| --- | --- |
| Suppliers & materials | CRUD, search, category/status filters, sorting, pagination |
| Requisitions | Draft → submitted → approved/rejected → converted; strict state machine; server-side validation |
| Purchase orders | Server-calculated totals (Decimal), issue/cancel, partial and full receipts with row locking |
| RFQs | Publish, record quotations, ranked comparison (price 50 / delivery 25 / supplier score 25), award → PO in one transaction |
| Analytics | Total/average spend, rejection rate, monthly and department spend, supplier performance, **supplier scorecard** (fulfilment 40%, on-time 40%, RFQ win rate 20%), date-range filters |
| Auth & RBAC | JWT, Argon2id, 5 roles (admin, procurement_manager, approver, requester, viewer), instant role changes/deactivation |
| Caching & jobs | Redis read-cache for analytics (versioned invalidation, fails open); CSV reports generated by an RQ worker |
| AI assistant | Claude tool-calling over the analytics services; deterministic rule-based fallback without an API key |
| Knowledge base (RAG) | Chunking → embeddings → Qdrant; answers with numbered citations and a `grounded` flag; retrieval evaluation (hit-rate@k, MRR, precision@k) |
| UI | Dashboard, suppliers, requisitions, orders (with receiving), RFQ comparison/award, analytics + CSV export, assistant chat, knowledge base, user admin |

## Architecture

```
React SPA ──► nginx ──► FastAPI (routers → services → repositories) ──► PostgreSQL
                              │            │                    └──► Redis ◄── RQ worker (reports)
                              │            └──► Anthropic API (assistant, RAG answers)
                              └──► Qdrant (knowledge-base vectors)
```

| Layer | Responsibility |
| --- | --- |
| `app/api` | Routing, permissions, dependency injection, error envelope |
| `app/services` | Business rules, workflows, transactions, cache invalidation |
| `app/repositories` | Query construction (filters, sorting, pagination, aggregations) |
| `app/models`, `alembic/` | SQLAlchemy models, constraints, versioned migrations (0001–0004) |
| `app/services/assistant`, `app/services/rag` | LLM abstraction + tools; chunking, embeddings, vector store, evaluation |
| `frontend/` | React application |

## Roles

| Role | Can do |
| --- | --- |
| `admin` | Everything, including user management |
| `procurement_manager` | Manage suppliers, materials, requisitions, orders, RFQs, knowledge base; approve; analytics |
| `approver` | Read; approve/reject requisitions; analytics |
| `requester` | Read; create, edit and submit requisitions; ask the knowledge base |
| `viewer` | Read-only, including analytics and the assistant |

## AI features

- **Assistant** (`POST /api/v1/assistant/chat`): Claude calls analytics tools (spend, scorecard, trends…) and answers only from
  returned data. Set `ANTHROPIC_API_KEY` (model via `ANTHROPIC_MODEL`). Without a key a keyword-based fallback answers the same questions.
- **Knowledge base** (`/api/v1/knowledge/*`): upload `.md`/`.txt` policies; `ask` returns an answer with `[n]` citations pointing at
  retrieved passages. Answers without a valid citation are flagged `grounded: false`.
  - `EMBEDDING_BACKEND=hashing` (default): offline lexical embeddings, no downloads.
    `EMBEDDING_BACKEND=fastembed` (after `pip install -r requirements-ml.txt`): semantic embeddings — also raise `RAG_MIN_SCORE`.
  - Qdrant is used when `QDRANT_URL` is set; otherwise an in-memory index is used (development/tests).
- **Evaluation:** `POST /knowledge/evaluate` or `python -m scripts.eval_rag` runs `data/rag_eval.json`
  (10 labelled questions) and fails with exit code 1 if hit-rate drops below the threshold.

## Development

```bash
python -m venv .venv && source .venv/bin/activate
pip install -r requirements-dev.txt
cp .env.example .env            # point DATABASE_URL at a local PostgreSQL
alembic upgrade head
uvicorn app.main:app --reload

cd frontend && npm install && npm run dev     # http://localhost:5173 (proxies /api to :8000)
```

Run the RQ worker locally with `REDIS_URL` set: `rq worker reports --url $REDIS_URL`.

## Testing

```bash
pytest                                              # in-memory SQLite; Redis/Qdrant/LLM are faked
docker compose --profile test run --rm test         # full suite on PostgreSQL, incl. migrations
cd frontend && npm run typecheck && npm run build
```

Covers state machines and money maths, every endpoint's success/validation/permission paths, a role-permission matrix,
database constraints, Alembic up/down on PostgreSQL, cache behaviour (fakeredis, fail-open), report jobs, the assistant tool loop
(scripted LLM), RAG chunking/embedding/retrieval/grounding and retrieval-quality thresholds.

## Configuration

| Variable | Purpose | Default |
| --- | --- | --- |
| `DATABASE_URL` | SQLAlchemy URL (`postgresql+psycopg://…`) | local PostgreSQL |
| `SECRET_KEY` | JWT signing key (≥ 32 chars; **required** when `ENVIRONMENT=production`) | dev placeholder |
| `ACCESS_TOKEN_EXPIRE_MINUTES` | Token lifetime | `60` |
| `ADMIN_EMAIL` / `ADMIN_PASSWORD` | Bootstrap admin when no users exist | unset |
| `REDIS_URL` | Enables analytics cache and the background job queue | unset (inline) |
| `QDRANT_URL` | Vector database for the knowledge base | unset (in-memory) |
| `ANTHROPIC_API_KEY` / `ANTHROPIC_MODEL` | Assistant and RAG answers | unset / `claude-sonnet-5-5` |
| `EMBEDDING_BACKEND` | `hashing` or `fastembed` | `hashing` |
| `CORS_ORIGINS` | Comma-separated allowed origins (not needed behind nginx) | `http://localhost:5173` |

## Deployment notes

- `docker compose up -d --build` runs everything with restart policies; the API applies migrations on start.
- Production checklist: set `ENVIRONMENT=production`, a random `SECRET_KEY`, strong `ADMIN_PASSWORD` (then remove it), real database
  credentials, and terminate TLS in front of the `web` container (reverse proxy / load balancer). Do not publish ports 5432/6333.
- Back up the `pgdata` and `qdrantdata` volumes; the Qdrant index can be rebuilt from the documents.
- Scale API replicas horizontally (stateless); run more `worker` containers for heavier report loads.

## Known limitations

- Access tokens are stored in `localStorage` (simple, but exposed to XSS); a hardened deployment would use httpOnly cookies + refresh tokens.
- No login rate limiting yet — put one at the proxy or add `slowapi`.
- Reference dropdowns in the UI load the first 100 suppliers/materials.
